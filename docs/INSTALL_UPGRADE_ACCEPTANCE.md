API 메타데이터와 로컬 해시·서명 검수 증거는 각 저장소의 Git 제외 `build/standardization/`에 있습니다. 05 다운로드는 공개 배포 파일이며 제한된 로컬 폴더의 권한을 변경하지 않았습니다. 04의 기존 공개 장부는 덮어쓰지 않습니다. 같은 바이너리라는 확인과 모든 배포 장부가 같은 바이트라는 확인을 구분합니다.

현재 PC의 제거 등록은 읽기만 했습니다. 04의 이전 QA 등록은 임시 AppId/임시 경로이며 운영 설치로 간주하지 않습니다. 실제 설치/제거 시험은 격리 Windows에서 해야 합니다. 이 환경에는 Windows Sandbox 실행기가 없고, 미서명 QA 실행/제거는 Windows Application Control에 차단된 전력이 있습니다. 정책을 해제하거나 우회하지 않았습니다.

## 기대 설치 흐름

1. 공식 서명·해시·대상 버전을 확인하고 현재 설정 전체를 백업합니다.
2. 기존 설치 위치/식별자를 찾고 구버전에 정상 종료를 요청합니다. 진행 중 자동화와 미저장 작업을 사용자가 확인할 수 있어야 합니다.
3. 종료·잠금 해제가 안 되면 새 파일 복사 전에 중단합니다. 강제 종료나 기존 폴더 전체 제거를 기본 동작으로 쓰지 않습니다.
4. 신버전을 반영한 뒤 설치 성공·파일 해시·이전 설치 소유권이 확인된 구형 EXE만 정리합니다. 사용자 설정·DB·매크로·작업 결과는 보존합니다.
5. 바로가기·파일 연결이 새 실행 파일을 가리키는지 확인한 뒤 신버전을 실행합니다. 사용자 자료 확인 후 이전 백업을 유지할지 결정합니다.

01·02·06은 고정 실행 파일 교체, 04는 버전이 포함된 구형 EXE의 설치 완료 후 정리, 05는 중앙 호환 목록의 구형 이름만 설치 완료 후 정리합니다. 07은 기존 AppMutex의 종료 안내/차단을 유지합니다. AppId·설치 위치·파일 연결·기존 단축키를 스타일 목적으로 바꾸지 않습니다.
