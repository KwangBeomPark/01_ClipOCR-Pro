# ClipOCR-Pro 배포 보호 2단계 검수

기준일: 2026-10-07. 버전 1.6.1·AppId·설정 위치·기존 공식 배포물은 변경하지 않았습니다. 소스 변경은 다음 버전 배포에 사용할 절차이며 실제 서명·설치·게시를 실행하지 않았습니다.

## 반영

- `build.ps1`은 저장소의 `build/`, `dist/`, `out/`만 출력 위치로 허용하며 `release/`, 저장소 외부, junction/symlink 경유 출력을 차단합니다. 기존 소스 건강 검사·컴파일 EXE 버전 검사·서명·컴파일 EXE 건강 검사 순서를 유지하고 정적 검사 및 배포 안전 회귀 게이트를 추가했습니다.
- 기존 개인별 `06_Stepwise` 서명 도구 경로를 제거했습니다. 명시 경로·환경변수·PATH·로컬 tools·Windows SDK 탐색을 사용합니다.
- 커밋·미커밋 상태·소스/설치/스크립트/자산/테스트 내용 해시·테스트 근거를 manifest에 추가했습니다. 기록 뒤 소스 변경도 검사합니다. 개발용 PFX·레거시 timestamp·컴파일 건강 검사 생략은 로컬 빌드에서 유지하며 공식 반영에서는 거부합니다.
- EXE를 서명한 후 ZIP 및 설치 파일을 만들고 설치 파일을 한 번만 서명한 뒤 별칭을 복사하는 기존 올바른 순서를 유지했습니다. `ReleaseSafety.ps1`이 필수 6개 자산의 정확한 이름·크기·해시·timestamped Valid 서명·서명자·체크섬·EXE/ZIP/설치 별칭·ZIP 내부 EXE 바이트를 다시 검증합니다.
- `release.ps1`은 시스템 서비스를 시작하거나 공식 폴더를 먼저 삭제하지 않습니다. 깨끗한 소스를 고유 `build/release-stage-*`에 빌드·서명한 뒤 전체 검증을 통과한 세트만 반영합니다. 이전 공식 폴더는 고유 `build/release-history/<시간-GUID>`로 보존하고 최종 이동 실패 시 복원합니다. 같은 버전 이름에 다른 바이트가 이미 있으면 교체하지 않습니다. 아카이브 이동은 기존 목적지가 있으면 실패하는 `Directory.Move`를 사용합니다. 전원 상실까지 원자적인 교체를 보장하지는 않습니다.
- `sign_release.ps1`은 위 절차로 위임하며 공식 EXE를 ZIP 생성 후 다시 서명하지 않습니다. 이전 인플레이스 재서명·불완전한 체크섬 갱신 경로를 제거했습니다.
- `publish.ps1`도 고유 stage 빌드·전체 검증 후에만 공식 폴더를 반영하며 미서명·레거시 timestamp 예외를 거부합니다. 기존 태그·draft·공개 릴리즈를 삭제하거나 덮어쓰지 않습니다. 기존 draft는 수동 검토·복구 대상으로 보존합니다. 성공한 전체 페이지 목록에서 draft까지 확인하며 새 자산을 올린 다음 원격 SHA-256 digest/크기를 재검증하고 draft 공개를 진행합니다. 게시 재시도에 자동 덮어쓰기나 삭제를 사용하지 않습니다.

## 설치 흐름

총괄 에이전트가 적용한 `CloseApplications=yes`와 첫 EXE 복사 전 `BeforeInstall` 쓰기 잠금 검사, `RestartApplications=no`를 보존했습니다. 새 EXE는 설치 완료 후 선택한 경우에만 실행합니다. 기존 고정 이름 EXE를 같은 위치에서 교체하고 `UserSetting` 및 기존 AppId를 유지합니다. 기존 앱 전체를 먼저 지우거나 강제 종료하지 않습니다.

정상 종료 거부·실패·취소·재부팅·사용자 지정 설치 위치와 제거 후 설정 보존은 실제 Windows 검증에 남습니다. 파일 잠금 검사만으로 실행 중인 프로세스가 전혀 없음을 증명하지는 않습니다. 기존 바로가기 정리는 유지하므로 파일 복사 실패 전에 일부 바로가기가 정리될 수 있습니다.

## 검증

- `tests/Test-ReleaseSafety.ps1`: **45개 assertion 통과**. 실패·불일치·별칭/ZIP 변조·기존 버전 충돌·아카이브 목적지 충돌·공식 이동 실패 롤백·원본 보존·위험한 진입점 거부·draft 페이지 조회·중복 태그 차단을 검사했습니다. 서명 검증은 격리된 mock이며 실제 서명 증명이 아닙니다. 실제 공식 폴더의 테스트 전후 해시는 동일합니다.
- 정적 검사 및 소스 건강 검사 통과. 공백을 포함한 고유 `build/phase2 verification <GUID>`에서 실제 미서명 Ahk2Exe·ZIP·Inno Setup 6.7.3 빌드 및 설치 정의 컴파일 성공. 컴파일 EXE 건강 검사는 개발용 옵션으로 명시적으로 생략했고 manifest의 `testsPassed=false`로 기록하여 공식화할 수 없게 했습니다.
- Antigravity `gemini-3.8-flash-high` / effort `high`를 사용해 보호 설계·래퍼 개선 초안을 검수받고 Codex가 독립 적용·검증했습니다. 토큰 세션을 확인한다며 임의 바이트에 시험 서명하는 제안은 실행하지 않았습니다.
