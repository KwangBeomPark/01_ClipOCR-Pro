# 6개 앱 공통 정비 2단계 종합 검수

검수일: 2026-10-07. 대상 01·02·04·05·06·07. LocalDataMart 제외.
이번 완료 범위는 소스 수정·자동 검사·격리 빌드·독립 교차 검수입니다.
새 인증서 서명·실제 앱 설치/업그레이드·GitHub 게시·커밋/push는 실행하지 않았습니다.

Windows Application Control의 미서명 실행 차단(4551/Code Integrity 3077)으로
1개 skip이며 실행 통과 수에 포함하지 않았습니다. 설치 파일을 실제 앱 설치에 사용하지 않았습니다.

각 프로젝트의 [상세 검수](STANDARDIZATION_PHASE2_REVIEW.md)가 해당 프로젝트 파일·검사·예외의 기준입니다.
여섯 프로젝트의 공통 기준/종합 문서는 같은 내용으로 유지합니다.

## 설치·업그레이드 흐름

기존 앱 전체를 먼저 지우는 방식을 사용하지 않습니다. 정상 종료 요청/종료 안내 후
파일을 교체할 수 있는지 확인하고 새 파일을 설치합니다. 고정 EXE 이름은 같은 위치에서
교체하며, 04의 버전별 EXE와 05의 호환 이름은 성공한 새 설치의 해시와 이전 설치 등록·경로·해시를
확인한 뒤 구형 파일만 정리합니다. 종료 거부·잠금은 설치 차단 대상으로 처리합니다.

01·02·05·06은 기존 설치 위치 재사용을 유지합니다. 04·07의 기존 고정 기본 위치 정책은
그대로이며 이전 사용자 지정 위치의 파일을 임의 삭제하지 않습니다. 07은 AppMutex로 사용자가
실행 중 앱을 닫도록 안내하고 차단하므로 자동 종료를 검증했다고 보지 않습니다.
설치 실패 전 일부 기존 바로가기가 정리될 수 있는 기존 동작은 실제 실패 복구 검수에 포함합니다.

실행 중 업그레이드, 활성 자동화/DB 작업, 다중 창, 종료 거부, 사용자 지정 경로,
취소·복사 실패·재부팅, 재설치, 제거 후 UserSetting·DB·매크로·결과 보존은 실제 Windows 게이트입니다.
파일 잠금 검사만으로 모든 프로세스·시작 경합·전원 장애까지 보장하지 않습니다.

근거: [정상 종료](https://jrsoftware.org/ishelp/topic_setup_closeapplications.htm),
[설치 이벤트](https://jrsoftware.org/ishelp/topic_scriptevents.htm),
[설치 처리 순서](https://github.com/jrsoftware/issrc/blob/main/Projects/Src/Setup.Install.pas).

## 보호·검수 기록

기존 공식 파일을 이번 작업에서 이동·덮어쓰기·재서명하지 않았습니다. 01·02·07은
담당의 작업 전후 공식 파일 해시가 동일하며 04·06의 공식 파일 수정 시각은 작업 이전입니다.
05 release는 접근 거부여서 실물 해시 검증이 남습니다. 권한을 변경하지 않았습니다.
04의 기존 사용자 수정 `docs/project-structure.md`는 원래 해시를 유지했습니다.
05 초기 직접 테스트 호출은 기존 로거의 실제 로그 위치에 진단 기록을 추가했으며 해당 로그를 임의 삭제하지 않았습니다.
최종 회귀는 프로젝트의 공식 검사 진입점에서 사용자 자료 경로를 격리해 실행했습니다.

Gemini 3.8 Flash High/effort high의 프로젝트별 구현 초안과 설치 정책 제안을 사용했습니다.
없는 빌드 인자/API/mutex, 무조건 덮어쓰기, 시험 바이트 서명 및 테스트 성공을 임의 부여하는
제안은 제외하거나 수정했습니다. 후속 시간 초과는 완료 근거에 포함하지 않았습니다.
Codex 담당 간 교차 검수로 테스트 출처·연결 경로 보호·서명 기록·draft 조회·외부 변경 롤백을 보완했습니다.

자동 승인 검토가 검수용 임시 복사본 폴더 정리를 정책상 거부했습니다. 상세 사유는 제공되지 않았고,
안전한 대안도 거부되어 추가 재시도는 중단했습니다. 시스템 임시 폴더의
`suite-appid-compile-9130bb4b612c4e37a2f74e59bc06940c` 복사본이 남아 있습니다.
프로젝트 내 격리 build fixture도 검수 자료로 유지했습니다.

다음 3단계는 02의 두 설정 저장소 통합과 여섯 앱의 백업·복원 계약 점검입니다.
설치 구조 중복·문서 경로·이름/기능 개선은 이후 단계로 유지합니다.
